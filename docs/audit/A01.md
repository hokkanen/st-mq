# A01 — two physical chargers and integrated remediation

The implementation follows the handoff topology: C1 = Easee; C2 = commissioned Shelly EVSE. TeslaMate/BMW are read-only vehicle feeds for either EVSE. Economic scheduling, physical connection, vehicle assignment, session request, metered energy and command ownership are separate. The only pre-1.0 compatibility boundary retained is v0.7.5 `easee.csv` / `st-mq.csv` import.

The hardware has not arrived. No real device/account/installation was contacted or operated. C2 defaults disabled and unverified; synthetic fixtures establish software behavior, not physical model/firmware semantics. The exact protocol profile and remaining hardware checks are in [provider capabilities](../charging-provider-capabilities.md); user policy and tradeoffs are in [Charging](../charging.md).

## Conceptual observations

- **OBS-A**: Preserved 0.925 efficiency and configured usable-capacity assumptions. Readiness is conditional; taper/temperature precision is not invented.
- **OBS-B**: Live per-phase source clocks/skew and additive-model commissioning are explicit. Statistical forecast and configured fuse evidence are separate.
- **OBS-C**: Per-charger/combined timing are labeled comparison metrics; no causal or annual savings claim.
- **OBS-D**: Each native transition retains pending/confirmed execution. Later pauses require availability and the final release has no final stop.
- **OBS-E**: Superseded for physical Shelly C2 only. Tesla/BMW remain read-only; no vehicle or generic relay authority added.
- **OBS-F**: Physical grid/diagnostic references, missing/unpriced coverage and supported CSV limitations remain visible. No native-development data repair ledger.

## Deliberate choices and limitations

- **A01-018:** retired current-probe experiments remain removed. The current active identification lifecycle has a persisted per-connection attempt and scoped pause proof; it never interprets old experiment state. Charging observation is limited to 60 seconds or 0.15 kWh and the response deadline is 90–91 seconds. Easee enforces pause expiry natively. Shelly restores through the application after safe readback, so process or MQTT loss can extend the stop. No automatic repeat or claim of an autonomous Shelly recovery timer is made. The unsent/possibly-sent distinction remains in real command paths.
- **Optimizer:** joint planning uses bounded search, a relaxed lower bound and honest gap reporting. Independent small two-job enumeration validates selected constraints/objectives. It does not prove exact continuous-time or all-input optimality; priority urgency remains a bounded approximation. A synthetic 24-hour two-charger run took about 0.47–0.49 seconds with 24 hourly price rows and 0.72–1.24 seconds with 96 quarter-hour rows on the validation machine. Planning is still synchronous: this is a known event-loop latency limitation, not a real-time responsiveness guarantee or unbounded search.
- **Native Shelly scheduling:** enabled native jobs preserve start/stop authority. The implementation does not infer an elapsed window from arbitrary cron expressions or edit native jobs. Disabling/removing native scheduling returns to a freshly computed ST-MQ plan; explicit manual stops remain protected.
- **Electrical model:** configured additive phase-current behavior must be verified. Neither asynchronous current arithmetic nor accepted 12 A fallback is hardware fuse protection. The current code has no demonstrated autonomous controller-loss watchdog. Status exposes this uncertainty; unattended deployment requires the later hardware verification described above.
- **Session diagnostics:** C2 uses the physical cumulative meter against a power estimate over exact known connection boundaries. Missing boundary samples/resets/gaps exclude the comparison. The native session-energy role is diagnostic until its reset semantics are verified. There is no old native-C2 repair or history conversion.

## Validation record

All regression paths are local and synthetic. Node 24 runs the current tests; loopback HTTP/MQTT fixtures use isolated ephemeral listeners. The targeted EVSE, late-BMW, request/identity and history run passed 73/73 tests; a later BMW field-precedence, native-ceiling, runtime and EVSE run passed 138/138 tests; the final source-freeze slice covering EVSE, physical-only MQTT startup, strict configuration, identity and current provider/equipment UI passed 160/160 tests; the [final validation report](VALIDATION.md) records the complete-suite and browser results. No skipped hardware work is counted as a passing test.

Specific numerical checks include revised-price 10 kWh × 40 ct = 400 cents, 6 A × three phases × 230 V = 4.14 kW, clipped-capacity uncertainty, independent two-job enumeration, tightest-phase 6 A pause boundary, fallback 12 A with stricter known limits, and 1/7/30/90-day rate/SQL work. Tests distinguish native readback from physical effect, older queued intent from a newer allocation, expiry after persistence, persistence-failed DUP retry and live confirmation of an initially retained state.

B12-006/007/008 are included: strict current charging and vehicle config, removed obsolete aliases/efficiency/topics, current runtime/controller readers, and strict replica saved-view reads. Current-schema restart is tested; development-format translation is deliberately absent.
