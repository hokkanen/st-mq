# Storage, pairing and application audit dispositions

Implementation against the supplied A01–A11/B12 package, based on
`f017684f708d0016978f27c40b291e7f2e222a59`. All fixtures use invented observations,
temporary databases and isolated services. Nothing here records household
commissioning or approval to actuate equipment.

## A08: recording and import

| Finding | Disposition and evidence |
| --- | --- |
| A08-001 | Fixed. Each import attempt gets an identity and unpublished raw/canonical staging. A retry replaces only its incomplete staging. A second source hash must agree before one transaction publishes observations, completion and the audit event. Synthetic A/B/A retries include shorter and longer replacement files and verify raw bytes, canonical values and foreign keys. |
| A08-002 | Fixed. `trainingRows()` reads the canonical import representation. It cannot revive invalid hexadecimal/numeric values or split quoted CSV again. Requested legacy heating modes remain requested evidence, not physical heat-pump confirmation. |
| A08-003 | Fixed. Staging has no observation IDs. IDs are allocated at verified completion, so publication cannot appear behind an already-consumed cursor. Interrupted import, intervening import, reopen, source-time reversal and duplicate retry are tested. |
| A08-004 | Fixed. Coverage lookup uses intervals containing the queried time, with stream identity and causal report times. Later outage extension, recovery or another device cannot manufacture earlier freshness. |
| A08-005 | Renamed and explained, rather than presenting an unproved compression-error estimator. `normalizedRmsChange` is normalized pre-update variation. UI and database descriptions make no recording-loss or accuracy-bound claim. An independent hold reconstruction of an exactly retained alternating-state trace has zero loss while the variation statistic is positive. |
| A08-006 | Fixed. Transaction cleanup recognizes SQLite automatic rollback and preserves the original error, including nested transactions. Real `SQLITE_FULL` injection verifies the failed state is absent and a later transaction succeeds. |

Primary regressions are `test/audit-storage.test.js`, `test/storage.test.js`,
`test/storage-snapshots.test.js`, `test/recorder.test.js`,
`test/learning-journal-index.test.js` and `test/chart-cursor-cleanup.test.js`.
Current-schema recovery and canonical historical chart readers are also covered
by the A07/A09 and A10 suites. Source CSV bytes are never rewritten.

Fresh databases use one final DDL, schema 14. Existing databases are checked
against that entire schema, version and foreign keys before writable pragmas.
Unversioned nonempty, obsolete, future and malformed files are rejected unchanged.
Restore validates the source read-only, verifies a private staging copy, and
publishes without overwriting a destination. There is no upgrade ladder, old-path
discovery, startup retirement sweep, coarse `learning_samples` table, dual inline
provider payload or automatic handoff seed.

## A10: authority, publication and recovery

| Finding | Disposition and evidence |
| --- | --- |
| A10-001 | Fixed at the MQTT publication boundary; see [transport evidence](A06-A10-transport.md). Authority revocation is synchronous before cleanup waits. Queued packets and stored QoS retransmissions cannot cross a lost connection/authority generation. Device receipt is still established by feature-specific readback. |
| A10-002 | Fixed. Repeated publication of the identical cached generation is idempotent. Existing immutable files are verified, never overwritten; conflicting metadata or bytes and invalid manifests fail without rewriting the publication. Verification receipt time is not immutable content identity. |
| A10-003 | Fixed. Peer polls carry the observation generation that started them. A result from before local handover cannot demote the new owner. A stale MQTT claim from the deliberately superseded peer is freshly challenged; confirmed competing authority retains its fail-closed behavior. |
| A10-004 | Fixed. Rejoin durably pins the same export, request identity, donor and release metadata. Export admission is reserved before the first await; creation, pinning and pruning share one mutation queue. A requested pin is committed before a new or cached export returns, closing the create-to-pin gap. The donor saves a matching release receipt with its role transition. Lost acknowledgement is reconciled by retrying that operation, including after both peers restart and newer unrelated exports, without inventing a new release. The UI exposes the pending operation for retry. |

`test/pair-authority.test.js` includes delayed observations and a lost release
acknowledgement followed by restart of both peers. Publication, exact-schema
validation, recovery merge and rejection of obsolete exports are covered by
`pair-recovery`, `pair-transfer`, `replica-sync`, `replica-viewer` and the extended
recovery/transport suites. Pair state has one current format (version 2).

The final independent review reproduced two retention races: concurrent export
requests passed admission before source validation completed, and pruning could
delete an export whose durable pin was created after the directory listing.
`test/pair-snapshots.test.js` now covers admission and failure recovery, both
pin/prune orderings, cached-export pinning and durable retention across restart.
A pin queued after deletion fails instead of acknowledging missing data. Peer
snapshot requests cannot request indefinite retention; only the local rejoin
operation uses atomic creation with a pin. The strengthened lost-acknowledgement
test makes three newer exports before restart and three afterward, then retries
the original release successfully.

Final focused validation on Node 24.21.0: **81 tests passed**, zero failures, in
`pair-authority`, `pair-recovery`, `pair-transfer`, `pair-snapshots`,
`replica-sync` and `replica-viewer` (`/tmp/stmq-pair-retention-final.tap`). Tests use
synthetic databases and isolated loopback peers; `git diff --check` passed.

Same-version recovery, lineage checks, durable restoration duties and standalone
SSH mirroring remain current features. A stale response is not treated as a
new authority, and “legacyOutstanding” remains an active restoration obligation.
No installed network VIP, household broker or physical failover was exercised.

## A11: lifecycle and deployment

| Finding | Disposition and evidence |
| --- | --- |
| A11-001 | Fixed. Closing synchronously stops mutation admission and suspends execution before waiting. Slow request bodies are rechecked against the current gate. Ordinary shutdown can still restore owned equipment while authority remains valid. |
| A11-002 | Fixed. Main, pair and slave runtimes register signal handling before awaited startup. Startup continuations check shutdown; paired child startup receives an abort signal. Tests interrupt initial control/startup work and verify cleanup. |
| A11-003 | Fixed. Worker failures and diagnostic/report callbacks are isolated and redacted; see [Home evidence](A02-A03.md) and `history-worker-errors.test.js`. A failed diagnostic cannot crash the control process. |
| A11-004 | Fixed. Repeated close calls share their completion promise. Cleanup attempts all resources, preserves restoration obligations, closes storage last and reports aggregate failure. Tests cover failed restoration plus failed pending-state persistence, overlapping close and startup failure. |
| A11-005 | Fixed. The commissioning guide describes current equipment commands and H66/readback behavior; retired `from_stmq/heat/action` instructions and scheduler entrypoint were removed. |
| A11-006 | Measured limitation retained with explicit observability. Synchronous SQLite waits can block all main-loop timers. Runtime status now reports event-loop maximum/p99 delay and a 1,000 ms warning threshold. A two-connection contention test measured approximately 5 seconds with the unchanged 5,000 ms durability wait, while verifying failed-write atomicity and recovery. No hard real-time guarantee is claimed. |

The 1,000 ms threshold is an operational warning budget, not a demonstrated safe
hardware deadline. Commissioning must establish device-side expiry and readback
margins for temperature renewal, frost control, temporary settings and charger
commands. Shortening every database timeout would risk durability without making
timers independent, so that suggestion was not adopted. Monotonic ownership and
expiry checks reject obsolete commands when work resumes. A separate control
process is a possible future design only if measured installation requirements
need it; it is not silently claimed as implemented.

The broad lifecycle regressions are `audit-lifecycle`, `equipment-api`,
`app-settings-reload`, `app-settings-reload-races` and `control-authority`.
`test/extended/storage-latency.test.js` uses real SQLite contention and an
independent timer/event-loop histogram.
