These modules are deterministic and perform no network calls or equipment writes. They use UTC instants (epoch milliseconds or ISO strings containing a UTC offset). Their tests use offline fixtures.

`prices.js` normalizes provider rows `{start, end, value}` using explicit units (`EUR/MWh`, `EUR/kWh`, or `c/kWh`), `vatIncluded: false`, and a source. It requires both interval endpoints, rejects overlaps, preserves gaps and negative prices, and uses actual durations. `allInPrice(instant, spotCtPerKwh, contract)` returns all components in c/kWh. `priceIntervals(normalizedIntervals, contract)` splits at rate and tariff boundaries. `costForPower(pricedIntervals, powerKw)` returns euros for an explicitly supplied constant import power; it does not infer heat-pump power.

Contracts contain `periods: [{from, to?, marginCtPerKwh, taxCtPerKwh, vatRate, tariff?, provenance?}]`. Bounds are inclusive/exclusive. VAT is a fraction; tax and retailer margin exclude VAT. Tariff defaults to `day-night`; `seasonal` must be explicitly selected. Transfer already includes VAT. All rates must be supplied; there is no default electricity tax or VAT. Billing outside supplied effective dates fails. To apply dated rates to another period, explicitly set `mode: 'scenario'` and `scenarioAt` to an instant covered by the desired rate period. The historical calendar still determines transfer day/night/season. Fixed monthly charges are outside marginal dispatch; a configured demand charge is rejected until a dedicated model exists.

Transfer schedules use explicit Helsinki weekdays, with no inferred holiday exclusions or automatic seasonal switch. The public [electricity configuration contract](../../docs/configuration.md#electricity-rates-and-historical-interpretation) documents the application settings and historical assumptions. Historical transfer prices also need verification: the supplied schedules describe the current contract and an alternative, and must not be declared historically effective without evidence. Tests use clearly synthetic tax/VAT values. Configuring actual tax/VAT requires checking effective dates against [Vero electricity tax tables](https://www.vero.fi/yritykset-ja-yhteisot/verot-ja-maksut/valmisteverotus/sahkovero/verotaulukot/) and [Vero VAT rates](https://www.vero.fi/en/businesses-and-corporations/taxes-and-charges/vat/rates-of-vat/).

`telemetry.js` provides `createH66Decoder({deviceId, verifiedRegisters?, maxAgeMs?, maxDuplicates?, duplicateWindowMs?})`. A message is `{topic, payload, receivedAt, sourceAt?, retained?, dup?, messageId?}`. Only `<device>/HP/<four-hex-digits>` is decoded; SET and CMD are excluded. Documented C60 MQTT registers default to engineering-unit scaling; optional `{scale, offset?, evidence}` entries record installed-device overrides. Plain MQTT has no acquisition timestamp: `sourceAt` remains null and the explicitly labelled `observedAt` uses publication receipt time. Fresh nonretained publications are usable within a bounded age, with gateway-cache and unknown measurement-time limitations retained. Retained, duplicate, invalid, stale and future-dated readings are excluded from control. Repeated identical ordinary readings are not automatically duplicates. MQTT DUP identification and supplied source identity use a bounded expiring cache.

Topic/register provenance was checked on 2026-09-06 against the manufacturer [MQTT specification](https://husdata.se/docs/h60-manual/home-assistant-integration/mqtt-specification/) and [Controller 60 list, revision 2025-10-03](https://online.husdata.se/h-docs/C60.pdf). The protocol tests are authored examples following those documents, **not captured installed-device traffic**. No particular hardware, firmware, wire scale or writable behavior has been commissioned. Room setting is not assumed to be the household's actual room-air target, operating-mode numbers do not imply a verified auxiliary policy, and auxiliary output is converted to estimated kW only with an explicit configured rated AUX power (default 9 kW); this is not a wattmeter.

`counters.js` provides `auxiliaryCounterDelta(before, after, options?)`, where observations contain `{at, compressorHours, auxiliary3kwHours, auxiliary6kwHours, dhwHours}`. The 3/6 kW nominal powers are explicit counter-interpretation assumptions, not measured electricity. Resulting auxiliary energy is labeled an estimate; no cause or fine-grained timing is assigned. DHW hours overlap operation and are never added as a separate electrical load. Reset, missing and implausible counters are not zero increments. `assessPhaseCurrents(legacyEaseeRow)` checks phase loading and data quality while explicitly returning null for active electrical power, energy and heat-pump power.
